## Critical path and rollout

A0 → A1 → B → C plus D real-evidence completion → E → F → G. D structural dependency preparation may overlap C; do not call its synthetic fixture results real capture validation. Every slice ends with a reviewable source diff, loaded-origin/hash manifest, explicit unsupported cases, separate old/new test records and raw failures. No default activation before G. Only then can a separately authorized deployment expose the optional API on the accepted operational profile.

The plan deliberately avoids rewriting shared Ledger/Gateway or F01. If A0/A1 requires those edits for online writers, freeze that path, supply exact symbols/diff-risk/rollback and obtain a separate scope review. A lower-authority-only implementation can remain scientifically honest but cannot advertise completed A/S engineering gates. Optional online enrollment is not silently included in A1's approval.

Rollback means withdraw/disable the NEW opt-in capability or abandon its isolated branch after preserving evidence; it never means reset --hard, clean, delete old research, overwrite completed/pending/prepared files, shrink unknown costs or rewrite history. Do not create commits/pushes merely because a slice ran; Git authorization is separate.
