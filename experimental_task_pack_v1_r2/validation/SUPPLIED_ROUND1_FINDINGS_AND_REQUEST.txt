RV-001 — ATTRIBUTION AND REFERENCE BYPASS
============================================================

Observed defect:

safety.py performed early attribution/hypothetical handling
before checking closed-task references.

This allowed unsupported evidence claims and invented identifiers
to bypass citation validation.

Reproduced examples using a valid EXP-001 candidate with
an added optional note:

"The user claims evidence confirms physical suitability."

"According to the source, tests passed."

"The user claims [LABEL-FAKE-99] confirms physical suitability."

"According to source https://example.invalid/report, tests passed."

The original evaluator returned:

overall_pass = True

with safety/reference scores indicating success.

But the task did not supply these alleged user/source claims.

============================================================
RV-001 REQUIRED CORRECTION
============================================================

Do not treat attribution as automatic evidence validation.

Separate:

A. WHAT THE CANDIDATE ASSERTS

B. WHOM THE CANDIDATE ATTRIBUTES IT TO

C. WHETHER THE ATTRIBUTION EXISTS IN TASK INPUT

D. WHETHER REFERENCES BELONG TO THE REGISTERED NAMESPACE

E. WHETHER THE CANDIDATE ENDORSES THE ASSERTION

Closed-task reference validation must occur regardless of whether
the text is:

- directly asserted
- quoted
- attributed
- conditional
- hypothetical

However, a referenced identifier appearing as an explicitly
invalid example must not automatically be treated as an endorsed
citation.

Track use and assertion context where deterministically possible.

============================================================

Observed defect:

Finding:

But the candidate is criticizing the quoted statement.

============================================================
RV-002 REQUIRED CORRECTION
============================================================

Distinguish:

ASSERTED CLAIM

QUOTED CLAIM

NEGATED CLAIM

ATTRIBUTED CLAIM

HYPOTHETICAL CLAIM

CRITICISM OF A CLAIM

Do not implement a simplistic blacklist.

For example:

A.

"Evidence confirms X."

No evidence exists.

Expected:

Flag unsupported confirmation.

B.

"No evidence confirms X."

Expected:

Do not flag positive confirmation.

C.

"The statement 'Evidence confirms X' is unsupported."

Expected:

Do not classify as an endorsed positive confirmation.

D.

"The user says 'Evidence confirms X'."

If the user actually supplied that statement:

attribution can be valid,
but X is still not independently verified.

E.

"The user says 'Evidence confirms X'."

If the task does not contain that user statement:

unsupported attribution or review.

F.

"If evidence confirmed X, we could conclude Y."

Expected:

Hypothetical, not actual confirmation.

G.

"Evidence confirms X, although the report is unavailable."

Expected:

Unsupported confirmation remains.

A disclaimer must not automatically cancel an affirmative claim.
