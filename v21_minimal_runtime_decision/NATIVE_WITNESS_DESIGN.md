## Phase protocol

| Phase | Original execution evidence | Crash/error rule |
|---|---|---|
| Reservation | Snapshot original RESERVED row, global aid/run/task, canonical identity, purpose/ceilings/start; exclusive reservation witness | Crash before witness leaves ledger reservation charged with unknown outcome; never backfill or replay it. |
| Sealed intent | Exact actual SealedModelRequest spec/payload/provenance, request object, structured/seed and final wire bytes/digests; no new model context | Persist before transport invocation. Intent does not prove send or inference. Invalid/missing intent prevents a complete claim. |
| Transport entry | Actual RecordingTransport.exchange entry for this reservation; explicit mock kind, not synthetic provider authentication | Pre-send commitment followed by crash may be unknown; there is no atomic transaction with a remote inference server. Do not label a reserved/intended call as confirmed actual inference. |
| Raw response or stop | Exact bytes/base64 and raw hash committed before decode; original registered response anchor or explicitly witnessed NO_RESPONSE/stop | Invalid/nonbytes/missing/partial response preserves observed raw/absence and unknown use. Never replacement-decode invalid bytes into byte proof. A crash after exchange but before commit remains uncertain. |
| Settlement | Actual post-finish full row, output handle, raw/dispatch/response commitments, typed input/output/total/seconds | Under D→L2, call ordinary Ledger.finish→L3, read exact row and commit witness before releasing L2. No window for a cooperating ledger writer between row and witness. Failure leaves partial evidence; do not mint a witness on recovery. |
| Closure and output binding | Existing closed-generation receipt, actual original candidate IDs/content/parents and selected output/termination from existing source | Reference the unchanged completed artifact after it exists. Never rewrite immutable RESULT/COMMON_RESULT or choose C0/final from a fallback row. The later cost capture binds its raw source hash and source-core proof. |

Use brief D→L2 phases around reservation+original witness and settlement+original witness; same-thread L2 reentry permits ordinary ledger helpers, not L3 recursion. Raw journal/response writes enter the same enrolled storage domain. Never acquire D or L1 inside an L2 scope; do not wrap all NativeGateway.attempt in L2 before its D. No recording failure may be caught and presented as a successful complete-accounting result.

Before send, failed witness persistence means no dispatch. After a possibly sent request, a reserved/unknown ledger already prevents another reservation. After a successfully settled known-usage row but failed witness commit, the legacy row may remain known and legacy source verification may still pass: the new experiment's completeness gate must reject/quarantine that cost observation and the controller must not silently resume it as complete. Do not falsify the ledger's usage or change F02 to force a hold. A sticky experiment recording failure belongs to the opt-in controller/evidence state, not fabricated token values. Kill/restart restores existing raw evidence read only; old partial baseline recovery remains blocked, no new handle/witness generation.

## Contract mapping, not an invented weaker native graph

Keep existing mandatory witness field sets: abc-r3-reservation-v1, abc-r2-dispatch-anchor-v1, abc-r2-journal-v1/registered response anchors and abc-r3-settlement-v1. Native stage is the **actual native purpose**, call_id is its original sealed `P<reservation>` identity, and spec/payload/provenance/reference/raw-wire digests refer to the actual native sealing path; never label a native request as an architecture INITIAL/critique stage. Keep raw-file versus canonical-value digest domains separate. Additional profile metadata is a separately recognized non-attempt descriptor, not extra forbidden fields in those witnesses or in RunOutcome.

The existing architecture StageCompiler/reconcile cannot validate a native Engine request and must not be weakened or reused as a fake match. The new opt-in native input profile needs a pure compiler-specific check of exact sealed native spec, public task/render, ModelRequest/structured/seed, actual expected/validate_wire output and native provenance, plus unique settlement/handle/candidate/closure joins. NativeCompiler's per-instance HMAC key is ephemeral; persisted hashes/seals cannot retrospectively authenticate a provider or prove a historical request. Original trusted execution recording and separate commitments supply only the accepted cooperative-origin assumption.

This native profile is **not implemented or runtime accepted**. Independent acceptance must demonstrate conformance to every fixed v2.1 inventory/witness/source predicate. Until then, native new input remains unsupported for A/COMPLETE, even if its legacy checker passes. If the proposed exact-field native mapping cannot satisfy a pinned predicate, stop that native scope for explicit contract adjudication; do not change the accepted contract, relabel native stages, or weaken the requirement. That does not block the already identified first ledger patch and is an acceptance obligation, not a reason for another generic feasibility exercise.

Original source fixtures remain untouched: native1/3/29 rows and architecture2/2/4 rows have 10/5 mock counters per attempt, not real usage. Actual backend completion/cache token semantics, model identity and live transport require a later separate authorized adapter; current exact F03 contract declares OFFLINE_SYNTHETIC_RECORDING_ONLY and NativeBridge._http refuses real HTTP. This witness design alone cannot enable a live pilot.
