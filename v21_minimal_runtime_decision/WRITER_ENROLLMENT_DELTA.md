# Minimum writer enrollment delta — proposed, not implemented

The smallest first production slice is a new opt-in shared-ledger L2 guard at `Ledger.lock`, with constructor/preexisting-resource checks and an ownership assertion at `_write`. It closes the demonstrated register/pending edge without editing register/reserve/finish separately. **It does not by itself complete IP01, confer A/S, or establish six-condition complete accounting.** Full relevant-namespace enrollment has additional small storage/creation boundaries. Do not describe a two-file ledger patch as full writer exclusion.

`cognitive_architecture_lab_v1/src/accounting/ledger.py`: constructor lines11–17 initializes under `self.lock`; `lock` line19 opens/initializes the L3 control before yielding; `_write` line41 writes/fsyncs fixed `.json.pending` then replaces main; `register`48, `reserve`53 and `finish`65 call `_write` under L3. `state`46 and `summary`83 also acquire L3 through `state`. A fifth direct call is the canary test at `runtime_isolation_v1/tests/canary/test_canaries.py:23`, also under `e.ledger.lock`. No additional direct `_write` call occurs in the 419-file checkout census. This does not prove no dynamic/external caller exists.

Gateway.register and NativeGateway.__init__ reach direct Ledger.register without D. Gateway.reserve_request/dispatch and NativeGateway.attempt hold D then use ledger methods; MockSession reaches Ledger directly. Current readers also take L3. Therefore enroll the class's common lock before it opens/initializes the L3 control, not merely Gateway.dispatch or register. Cover constructor parent/control creation in the opt-in bootstrap/preflight; a guard around os.replace is too late to exclude pending creation.

## Lock graph and resource identity

Creation path: G→L1 or binding lock B as required→L2→ordinary L3. Existing exchange path: L1 when supplied→D→L2→L3. Event/sink path outside D may use L1→L2, or L2 alone. Capture takes G to exclude namespace admission, proves/drains the declared active writers, then existing L1→L2; it never takes D/B/G after L2 and never holds L3 over the unchanged completed verifier. D→L2 is safe only because no L2 critical section calls D. **Never wrap an entire Session.call, baseline, Gateway.dispatch or NativeGateway.attempt in L2 before its existing D acquisition.** That creates L2→D versus D→L2 inversion. Existing D and L3 are not made reentrant.

New L2/G contexts need checked logical reentry for the same process/thread/resource across separate Ledger objects, so an observer's ordinary source verifier can call state while owning L2 without reacquiring the OS byte lock. Native L3 is acquired normally once; recursive L3 remains prohibited. Reject duplicate module origins, cross-thread/process ownership-token reuse and inherited stale contexts. Control waits stay within the approved maximum5 seconds and capture at most2 acquisition attempts; no retry after an in-cut violation.

Use a stable logical resource identity bound to the canonical parent directory/volume identity and normalized ledger basename plus preexisting domain control/profile, not the current ledger file ID alone: atomic replacement legitimately changes that ID. Validate actual current identities at capture; reject hard-link aliases/reparse/case-collision escapes rather than assigning different guards. Never derive guard identity only from spelling, run ID or an unhashed caller assertion. Bootstrap namespace changes occur before admitting writers, under G/L2, not inside a capture. Unknown or missing required enrollment metadata is an error/downgrade; a new instance must not silently regain a legacy bypass on an enrolled resource. Non-enrolled paths retain legacy mode.

All existing-file control paths must be precreated/nonempty before strong capture; otherwise unchanged dispatch_lock/Ledger control initialization can create bytes. Active/unknown owners or undrained finally work prevent admission. No process census, stable hashes or a metadata flag alone proves coverage. This remains the accepted cooperating-writer model, not hostile-host enforcement.

## Is complete enrollment one small slice?

No. The ledger convergence is a small independently reviewable slice, but full enrollment also requires closure, durable/append sinks, creation admission and actual L1-protected caller coverage. Native durability and same-cut parsing/source proof are separate. Editing forty callers is unnecessary; claiming all forty are covered by Ledger.lock is false. The bounded 1,404-edge static census includes unresolved candidates and test/history paths; dynamic/external actors remain explicit admission limits. Independent acceptance must validate the scoped source graph and actual NTFS behavior, not just this table.
