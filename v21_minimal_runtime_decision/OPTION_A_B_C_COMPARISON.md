# Option comparison and recommendation

**HYBRID_BOUNDARY_RECOMMENDED.** This is an authority policy over the minimal common writer/witness work, not a shortcut around all-writer proof. It does not require a new general I/X observer package. Reuse existing honest source diagnostics; request strong authority only at the terminal experiment accounting/source cut. Every relevant producer still coordinates when it can mutate that cut's inputs, not just when the certifier runs.

| Dimension | A — minimal writer-domain enrollment | B — I/X-only restricted research | C — hybrid terminal boundaries |
|---|---|---|---|
| Exact source delta | Ledger.__init__/lock/_write + new coordination module; closure write scope; durable and append sinks; creation admission/remaining mkdir and wrapped-baseline preconditions; native witness/glue and authoritative capture/parser/source proof | No producer changes; optional new separately named read-only manifest consumer over existing evidence, no replacement verifier; preserve legacy eligibility separately | Same necessary ledger/storage/creation/witness delta as A for the scoped terminal cut; reuse existing L1 and post-generation drain; existing diagnostics remain I/X, no new all-purpose observer |
| Scientific capability | Prospective complete comparable recorded calls/validated usage, only after all cut/source/witness gates | Useful candidate/receipt/condition-fidelity observations and a separately approved quality-only endpoint over eligible legacy source | Study A can remain separately gated; Study B gets full strong proof only at its necessary endpoint, partial/intermediate fields remain narrow |
| Remaining limits | No provider authentication/billing/semantic correctness; current runtime stack and native profile still absent | No complete historical coverage, A/S new eligible view, full totals or cost-efficiency ranking | Same complete-cost requirements and provider limits as A; unsupported/old/active source modes stay lower or reject |
| Compatibility risk | Changes common Ledger read/write boundary and source sinks; non-enrolled legacy behavior must remain | Lower source risk, but reader can mislabel stale/partial facts or wrong candidates | Same common-writer risk as A; deliberately narrower supported source/mode/admission surface, no producer bypass |
| F01/F02 risk | Recursion/order, late logging, constructors and source pin seams; preserve all old primitives/checks | Accidental VERIFIED/BLOCKED promotion or reader calls that log/write inputs | Same hard preservation gates as A; strong certifier always calls unchanged core at same cut, diagnostics never stand in |
| Native durability | Mandatory new execution-time native reservation/intent/raw/settlement witnesses and accepted native mapping | Current asymmetry remains disclosed; no complete cost claims | Mandatory for Study B; optional diagnostic fields cannot stand in for it |
| Test obligations | Real direct Ledger APIs/readers, constructor/control paths, cross-run/shared resource, sinks/late writes, native crash windows, exact faults, full affected regressions | No-write/origin/candidate/missing/unknown/reader controls; no fake full totals | A's complete relevant-cut tests plus explicit lower/strong branch separation, post-terminal admission and no active-source fallback into A |
| Independent gates | IP01–IP09 relevant source/capture/semantic/compatibility/runtime acceptance; no documentary discharge | Fresh read-only consumer/legacy-source and quality-protocol acceptance; runtime/provider gate still separate | Same mandatory strong prerequisites as A wherever A/S/COMPLETE is claimed; lower observations never waive them |
| Estimated effort, not measured | 20–35 engineer-days +8–12 reviewer-days for scoped native witnesses/capture/integration/affected acceptance | 5–9 engineer-days +3–5 reviewer-days for a limited manifest consumer/quality protocol; excludes live-adapter work and cannot meet cost endpoint | 20–35 engineer-days +8–12 reviewer-days for the same strong endpoint plus reuse of existing diagnostics; no asserted saving over A's minimum producer work |

Estimates assume one Windows/NTFS platform, existing task/settings/source policy, no Engine/Harness/evaluator or algorithm edits and reusable tests/tooling. They are uncertain planning estimates, not measured velocity or promises. Real backend transport/admission, new schema dependencies and human scientific adjudication are not included. The first ledger slice alone is estimated3–5 engineer-days +2–3 reviewer-days and does not enable complete accounting. Missing IP03–IP08 runtime components are not costed as already installed.

A and C have **the same minimum relevant-writer coverage obligation**. It would be misleading to claim that hybrid certifier-only locking removes the need to enroll register, closure, journals, pending names or late events. C is recommended because the experiment needs authoritative total cost only at a declared terminal cut; it gains nothing from certifying every exploratory diagnostic. This policy avoids building an additional general observation platform while preserving the whole strong boundary where the claim requires it. A is also a valid framing of the mandatory writer part; no artificial source-line saving is claimed. B alone knowingly fails the intended complete-cost claim.

Do not implement forty caller edits: use audited storage/creation chokepoints plus verified existing L1 paths. Do not pretend the first Ledger patch closes the entire writer graph. Full scoped enrollment is not one tiny patch because closure, directory creation, late events and native durability are independent of Ledger._write. These are identified implementation boundaries with finite acceptance gates, not a request for another broad feasibility study.
