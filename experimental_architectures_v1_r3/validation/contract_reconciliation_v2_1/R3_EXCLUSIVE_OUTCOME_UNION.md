# R3 normative disjoint serialized views

Schema version end-outcome/2.1-proposal.1; contract end-certification/2.1-proposal.1. Three serialized variants and one NONserialized error category:

1. ELIGIBLE_NORMAL_TERMINAL: referenced source artifact exists and passes the existing completed-verifier at the common guarded cut; source provenance VERIFIED; reason is COMPLETED, NO_ACTIONABLE_REVISION, INVALID_RESPONSE or PROTOCOL_FAILURE.
2. ELIGIBLE_RESTRICTED_TERMINAL: same source verification/persistence requirement; either source provenance VERIFIED and reason INTERRUPTED, BUDGET_EXHAUSTED, TIME_EXHAUSTED, EXTERNAL_BLOCKER or UNRESOLVED; OR provenance INTERRUPTED/UNKNOWN and reason one of those five plus INVALID_RESPONSE/PROTOCOL_FAILURE. Thus a verified persisted INTERRUPTED record is ALWAYS RESTRICTED, never NORMAL. COMPLETED/NO_ACTIONABLE_REVISION with uncertain provenance matches neither and must fail.
3. NONCERTIFYING_DIAGNOSTIC: source eligibility is NOT asserted, no selected certified candidate and no normal source publication descriptor. INTEGRITY_HOLD means grounded BLOCKED; SNAPSHOT_AUTHORITY_UNAVAILABLE/UNSUPPORTED_OBSERVATION means UNKNOWN, not fabricated corruption. An explicit trusted adapter decision may retain grounded observations even if a common cut cannot be acquired. This is not an expansion of the current execute/blocked_recovery catch boundary.
4. TYPED_INTEGRITY_REJECTION_OUTSIDE_JSON_UNION: a typed error channel, NOT a fourth serialized member. Current RecoveryIntegrityHold/ArtifactIntegrity retain their existing behavior. An opt-in adapter may construct a NEW, independently validated diagnostic only from a recognized grounded cause; arbitrary I/O/programming exceptions remain real errors. Unknown/unbound context cannot fabricate an envelope.

## Deterministic routing, in order

If a recognized grounded diagnostic cause is supplied, use member3 with its exact cause/provenance combination. Otherwise source verification must succeed at the same guarded A/S cut as its referenced bytes/identity/closure. VERIFIED + normal reason => member1; VERIFIED + restricted reason OR uncertain provenance + allowed uncertain reason => member2. Every other input stays outside serialization with the appropriate typed/operational error. No producer chooses a class by preference. Never promote current graph.overall or an earlier source check to a same-cut proof.

## Independent terminal meanings

ARTIFACT_PERSISTED (artifact_persisted) describes the REFERENCED source record/diagnostic file, not persistence of the returned view/envelope. Member1/2 require true and a verified existing legacy normal source path/hash/check ID; the view is not inserted into or substituted for F01 RESULT bytes. Member3 true means a unique diagnostic file under publication/recovery_holds; false means NO_ARTIFACT. Its envelope can still be returned in memory. A prior normal RESULT is only prior_artifact_observation with currently_verified=false, never the diagnostic publication target.

PROVENANCE_ELIGIBLE means the existing source boundary passed for member1/2, not that every stricter new R1 accounting witness exists. Legacy-valid source may have a guarded S new observation view and null complete totals; its original eligibility is not redesigned. Missing common-cut authority permits only a noncertifying diagnostic, while legacy APIs/artifacts remain unchanged. BLOCKED is never eligible.

TERMINATION_REASON is the source algorithm/control termination for member1/2. Member3 has EXTERNAL_BLOCKER plus a distinct diagnostic_cause. ANSWER_SUCCESS is NOT_ASSERTED for every member: even COMPLETED is an algorithm termination, not semantic correctness. CANDIDATE_SELECTED is a separate boolean/ref relation governed by verified source binding. SCIENTIFIC_SCORE_AVAILABLE is always false, score_status NOT_COMPUTED and score null. No diagnostic/model/schema fixture yields an empirical score.

Known unknown source usage never becomes a successful source terminal: the unchanged source closure/eligibility gates must still pass. The outer accounting field may be PARTIAL because stronger R1 capture coverage is unavailable even when a legacy source is valid; that is not a claim that unknown current source cost is known. COMPLETE new totals require A + VERIFIED + complete raw/usage/closure coverage. INCONSISTENT new accounting cannot accompany an eligible source view; it produces/requires actual integrity rejection or a noncertifying diagnostic instead.

## Required fields, absent/null/empty and candidate semantics

R3_SCHEMA_SPECIFICATION.json defines the closed object grammar, exact enum values, three oneOf members, nested candidate/accounting/publication objects and REQUIRED x-semantic-rules. R3_NORMATIVE_FIELD_MATRIX.csv is generated from those same definitions; it is not a separate conflicting authority. Additional properties are forbidden at every object. Legacy result/C0/FINAL/initial_candidate/final_candidate/implementation_version/artifact_payload_sha256 are forbidden outer fields, including null-valued attempts to smuggle them in. No embedded legacy result-looking payload is allowed.

ABSENT means forbidden/not part of that structural branch, e.g. diagnostic_cause and prior_artifact_observation are absent in eligible members; missing discriminator is INVALID. NULL is permitted only for explicitly defined unverified/unavailable values WITH state: selected_candidate_ref null iff candidate_selected false; complete_totals null iff state not COMPLETE with a reason; missing content/lineage has MISSING/UNAVAILABLE plus reason; scientific_score null only NOT_COMPUTED. EMPTY is a known empty collection at its stated scope, never an inferred zero: candidate entries=[]/NONE_SUPPORTABLE means no justified observations, not zero historical candidates; KNOWN_EMPTY_HISTORY additionally requires positively verified complete coverage.

OBSERVED candidates carry original IDs/content hashes/attempts/source refs and observed handle/lineage authority. Missing bytes remain missing. SELECTED means exactly one ref exists and its candidate is PRESENT, source-bound, response-eligible, verified lineage and bound handle. SOURCE_VERIFIED_BINDING/CERTIFIED means selection/content binding within declared source proof only, never answer correctness. A diagnostic has candidate_selected=false/ref=null and forbids source-certified candidate/handle labels. With no supportable candidate observations it explicitly has observation_state NONE_SUPPORTABLE (or UNAVAILABLE), history_coverage UNKNOWN, entries=[], initial_ref null/NOT_KNOWN and a reason; it must not fabricate C0 or an empty verified history.

The original initial candidate is retained as a bound initial_ref only when actual source proof identifies it; never assign C0 by array index after corruption. A restricted terminal may retain/select an independently supported valid C0 while a later attempt/cost is unresolved. INVALID_RESPONSE can preserve rejected raw content without selecting it; a previously valid C0 may remain selected if source proof allows it. Rejected/unassessed/missing/unbound candidates are never selected. Output-handle proof requires exact run/task/call/attempt, wire/provenance and settlement bindings, uniqueness, parent order and settled-before-reference. Dynamic ref equality, content hashing, origin/cut proof and complete-cost sums are mandatory semantic rules, not merely schema shapes.

Structural validation AND every x-semantic-rule with trusted external source/capture evidence are required. Caller booleans/checksum matches never authenticate those external predicates. The synthetic fixture checker uses declared synthetic evidence oracles only; it is not a runtime adapter, snapshot extractor, verifier replacement or migrated acceptance suite. Every valid serialized fixture must match one member; contradictory fixtures must match zero after the complete normative checks. A typed error matches zero serialized members by design.

## Exact diagnostic-cause boundary

INTEGRITY_HOLD requires a real grounded BLOCKED rejection and may retain A/S or lower observations. SNAPSHOT_AUTHORITY_UNAVAILABLE and UNSUPPORTED_OBSERVATION describe unavailable/unsupported capture authority (never an arbitrary programming exception), require UNKNOWN provenance and I/U/X only. A stable A/S cut whose requested source format/verification operation fails for another reason is not relabeled as snapshot-unavailable: the declared typed/operational error propagates, with retained observations in its context, outside this serialized union. Unsupported run context never fabricates a diagnostic. The current execute()/blocked_recovery exception boundary is unchanged.

For mathematically integral JSON numbers, draft-07 integer typing applies; booleans are never integers. Real source witness parsing still follows the source's exact type/hash requirements. The forbidden outer legacy completion field is_completed_result is rejected even when false or null; the new field is artifact_persisted with its explicit referenced-source scope.

Digest domains are exact: publication.sha256/evidence_ref.sha256 refer to raw captured file bytes; run_binding.identity_sha256 uses the baseline canonical identity value; no legacy artifact_payload_sha256 is substituted. The trusted external source check must compare every run/task/condition/path/hash/candidate/ref to the same captured facts, not merely accept a caller-rehashed candidate or a matching digest at a foreign path.
