# R1 normative authority classes

A coherent snapshot is a view of BOTH membership and bytes, not a bag of matching hashes. Source origin, capture consistency, accounting graph validity, raw-journal validity and full-run certification are independent dimensions. No class below authenticates provider inference or arbitrary hostile-host activity.

## Cooperative trust boundary

An authoritative cut requires an audited writer-domain description naming every cooperating mutator of this run identity, ledger/closure, owner/publication metadata, witness namespace and journal namespace. All such writers must serialize through the declared existing publication/run guard and outer shared-ledger mutation-domain guard in the same order. The domain description records protocol version, code identities, guarded resource identities, participant coverage and trust assumptions. A caller boolean, timestamp, current graph.overall or a file hash is NOT a domain attestation. If writer coverage cannot be established, no high class is available.

NTFS read handles denying write/delete sharing protect only the open existing files for their lifetimes. They do NOT prevent creation of a new directory entry or authenticate who originally wrote a file. The common cooperative guard, not a directory hash, excludes membership changes by participating writers. No directory freeze, hostile-user prevention, provider signature, hardware power-loss or distributed-filesystem property is claimed. Uncooperating actors with equivalent OS privileges are outside the qualified cooperative guarantee; if such interference is observed/suspected in the capture, downgrade as specified. Before/after equality cannot rule out ABA and never establishes coordination.

## Exact classes (apply priority U > A/S > I > X)

| Class | Exact prerequisites | Permitted claims / limits |
|---|---|---|
| AUTHORITATIVE_CONSISTENT_SNAPSHOT (A) | Verified cooperative domain; all declared guards held from enumeration through sealed in-memory capture; full recursive namespace inventory and pinned contents/identity/ledger included; no observed violation; closed mandatory ACCOUNTING witness graph with exact IDs/commitments, no unknown eligible members | ANCHORED_GRAPH_CARDINALITY over that visible anchored set, plus source-grounded narrower metadata. NOT provider inference or complete cost by itself. Raw journal contents may be corrupt/missing; this is explicitly recorded and still blocks R2 normal certification. |
| STABLE_BUT_INCOMPLETE_OBSERVATION (S) | Same coordinated complete membership/content cut, but a mandatory accounting witness is absent, rebound, duplicated, inconsistent or unknown/unexpected eligible member prevents graph closure; at least one supported witness fact remains | Corroborated identity groups/recorded metadata only; NO anchored-graph cardinality tier or complete accounting claim. Stable view of contradictory data is not a coherent accounting graph. |
| INDIVIDUALLY_CORROBORATED_OBSERVATION (I) | No common cut proven; at least one retained single source or independently bound source group can be read/pinned and its individual identities/commitments checked; capture times/scopes are explicit | Only per-source/group observations, possibly numeric distinct identities WITHIN THAT GROUP, never a graph-wide snapshot count, absence/completeness assertion or full-run cost. Separate timestamps/hashes never upgrade I to A/S. |
| UNSTABLE_SNAPSHOT (U) | A required guard/pin/domain assurance was violated, or content/membership/identity changed during the purported guarded cut, including known ABA; stronger capture aborted | No strong claims from that capture. Retain safely captured individual facts under explicitly lower per-claim authority; otherwise no observations. Do not reuse a prior A value as a current A value. |
| UNSUPPORTED_OBSERVATION (X) | No coordinated cut and no justified readable/grounded ATTEMPT/accounting identity fact; or context cannot be grounded | Empty observations with explicit unsupported reason, not observed zero. If run identity cannot be grounded, no outcome envelope is fabricated: propagate a typed operational/integrity error. |

A versus S is about a closed accounting identity graph, not successful raw-response validation. The required acquisition inventory still includes every raw journal and its registered absence/content. The fourteen controlled wire-damage cases can remain A for anchored cardinality only if all independent mandatory accounting witnesses close and the acquisition protocol holds. A raw duplicate that is demonstrably the identical representation of the same registered known identity, or a known moved journal, is inventoried/classified and never counted as another attempt. An unknown/unbound extra raw member or any unexpected independent attempt member makes closure S; it is never ignored. This distinction preserves the sixteen conclusions without concealing unexpected records.

## Claim authority and mandatory observation preservation

Each claim has claim_kind, value, evidence_authority, scope/run/attempt IDs, source_refs with exact path/hash/origin, snapshot_id, verification_status, limitations and full_run_certification_permitted=false. Exact machine types are in R3_SCHEMA_SPECIFICATION.json. Identity-group claims distinguish separately captured execution-origin channels from mere copies of one mutable ledger; filenames/hashes alone do not establish recording origin. Unknown origin downgrades to RECORDED_IDENTITY/UNVERIFIED.

ANCHORED_GRAPH_CARDINALITY requires A and exact closed-set ID coverage. It is a count of recorded anchored identities, not real inference. CORROBORATED_RESERVATION_DISPATCH requires both original reservation and dispatch witnesses. CORROBORATED_IDENTITY_GROUP can preserve a different valid multi-channel identity group when one witness class is missing; name its channels and failed dimensions. RECORDED_IDENTITY retains a single source claim without upgrading origin. Settlement/response/usage metadata have independent statuses; a retained number may be observed even while its current binding conflicts.

Every justified narrow fact MUST remain reportable; a failed strong proof must not erase readable facts. Claim values refer to exactly their source group/capture, not a larger unstated set. Positive zero requires a proven empty covered set, never an empty/damaged ledger. Full totals require complete usage/settlement/raw/closure coverage and independently eligible source provenance; otherwise complete_totals=null with a reason. No BLOCKED source, A snapshot, matching checksum or supported count can grant normal certification. R2 remains separate and unchanged.

Existing current helpers do not implement this protocol. In particular graph VERIFIED may omit a reservation, and standalone enumeration can miss a later orphan. Those statuses cannot be used as authority tokens for the future extractor. All claims in this proposal are conditional requirements for future separately authorized code.

The run context may be grounded while no attempt observation is supportable (X). Run identity is not an observed zero-attempt set. Distinguish L2 outer domain exclusion from the inner non-reentrant Ledger.lock as defined in ACQUISITION; a merely existing dispatch guard is not coverage proof.

When X applies, no typed candidate with a justified attempt association is emitted either: a supported candidate/attempt association itself supplies at least a recorded identity and cannot coexist with a claim that no attempt fact is supportable. A grounded run identity may still permit a no-supportable-observations diagnostic. Raw uninterpreted bytes can be retained as evidence references without inventing a candidate.
