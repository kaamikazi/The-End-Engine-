# Prospective guarded-cut acquisition (no implementation)

Protocol: R1-GUARDED-CUT-2.1. One run and its actual shared ledger per capture. Total acquisition attempts <=2, each waiting <=5 seconds for guards; at most one retry. No attempt reserves, dispatches or replays a model call, reconstructs a historical witness, resets budgets, claims a new owner/fence, releases another owner's lease, repairs files or rewrites results.

## Acquisition and release boundaries

0. Resolve a preexisting grounded run identity/request/ledger binding without constructing a Session or Publication that could create metadata. Verify canonical allowed root/path identities. If missing/foreign/unreadable identity prevents grounding, stop with a typed error; do not invent a run ID or emit a fake envelope.
1. Verify the cooperative writer-domain evidence defined in AUTHORITY and the resource/code/participant coverage. It must explicitly cover all producers of names/content, including reservation/dispatch/receipt/settlement hooks, closure and ownership writes, and shared-ledger writers. No coverage evidence => no A/S; use I/X only. Current code is NOT presumed to provide a ready-made observation-domain token.
2. Acquire the existing run/publication coordination guard, then the outer shared-ledger mutation-DOMAIN guard (L2), distinct from Ledger.lock (L3), in the audited writers' same order. Do not acquire/increment an owner lease/fence for observation. On busy/deadline before the boundary, release anything acquired and retry once; after a second failure return I/X evidence or a grounded SNAPSHOT_AUTHORITY_UNAVAILABLE diagnostic, never normal v2.1 eligibility.
3. Acquisition boundary B occurs only when outer guards L1 (run/publication) and L2 (shared-ledger domain) and domain assurance are held. Enumerate the complete relevant inventory recursively, with names, entry types, canonical paths, file identity and expected registered missing paths. Include identity, complete ledger envelope/rows, relevant closure/owner/source-publication files, all entries under publication/attempts and wire, moved/temporary/unknown files and directories. No '*.json'-only walk. Reject/mark links/reparse points, alias/hard-link identities, case-fold collisions, path escapes and unclassified entries. A duplicate file cannot become an independent channel or new attempt.
4. While retaining both guards, open read handles that deny writes/deletes to each existing inventory file, using the already established Windows local semantics. Pins protect existing content only; the cooperative namespace guard protects membership. If native semantics/guard coverage cannot be established, downgrade; do not substitute a before/after hash loop. Optional platform implementations need separate proof/review; none is asserted here.
5. Read pinned bytes into capture-owned immutable buffers. Capture run identity, ledger/closure/owner/request binding and all expected/missing witness descriptors. Parse strict finite duplicate-key-free JSON; validate global reservation order and own-run ID set without discarding foreign rows before ledger integrity checks. Match all origin/schema/run/task/stage/attempt/intent fields and independent commitments described in WITNESS_REQUIREMENTS. Never call helper methods that reacquire these non-reentrant locks; a future read-only pinned-buffer parser is required under separate scope.
6. Re-enumerate the COMPLETE namespace while still holding both guards and all pins. Compare names/types/file identities/registered absences and revalidate pinned contents plus identity/ledger bindings. Equality is a consistency assertion under the already-established cooperative exclusion, NOT proof against arbitrary mutation or ABA. Any mismatch or observed guard/domain violation aborts stronger claims and yields U. An actor that changes and restores a name under the guards is a domain violation even if equality happens to pass; undetectable hostile ABA is excluded, never claimed prevented.
7. Classify every member: required witness, registered raw journal, recognized moved/duplicate raw representation of an already anchored ID, known non-attempt metadata, or unclassified/unexpected potential attempt evidence. No silent discard of unknown/temp/extra names. Explicit expected-but-missing descriptors are in the manifest. Validate graph closure independently of current graph.overall. Complete closed accounting graph => A; stable cut with missing/contradictory/unknown coverage and surviving facts => S; retain failed raw integrity separately.
8. Seal an in-memory capture manifest and all referenced bytes/absences before releasing guards. Manifest fields are protocol_id, capture_id, run/ledger/resource identities, writer-domain evidence reference, boundary/release ordering evidence, complete inventory with path/type/file-identity/hash or explicit absence, witness membership/crosslinks, validation failures, authority class and digest over canonical manifest/byte references. Its producer origin is a trusted cooperative capture assumption, not authenticated by its digest. If persisted later, use a NEW diagnostic/capture file only; hashes cover previously captured buffers, not reread mutable paths.
9. If producing an eligible terminal view, invoke the unchanged existing completed-verification core (the current Publication._verify_completed path, including verify_semantics/independent eligibility) in a non-owning, grounded context against the SAME guarded state/source bytes before release; bind its result/identity/closure/report and capture_id to the envelope. A legitimate legacy source may verify while stricter R1 mandatory coverage is S; preserve its legacy eligibility without claiming new complete accounting. If a common cut cannot be established, do not claim a current eligible v2.1 terminal: retain the legacy artifact untouched and emit only a grounded noncertifying snapshot-unavailable diagnostic or typed operational failure. This changes no existing legacy API behavior.
10. Release boundary E is after the manifest/buffers/eligibility checks are sealed, before returning a view. Close pins and release shared-ledger guard then run guard on every exit path. Do not retain mutable file handles as future proof after release. Any later reader verifies capture integrity AND qualified producer origin/authority; timestamps or hashes alone do not authenticate historical recording.

## Retry and concurrency failures

Only transient inability to acquire guards/pins BEFORE B permits one retry (2 attempts maximum). A stable semantic absence/conflict returns S immediately with reason; no repair/retry to make it disappear. Any mutation/guard/domain violation DURING B..E invalidates the domain epoch: U, zero strong retries in that epoch, preserve lower facts. A new trusted domain epoch may be established only through a separately reviewed operational action, not by automatically polling until hashes match. Repeated mutation => U, no provider call and no normal v2.1 view/certificate. If the environment never supplies adequate coordination, I/X is the correct limit, not an invented filesystem guarantee.


## Lock identity and verifier feasibility (normative clarification)

L1 is the existing per-run publication coordination guard. L2 is an OUTER shared-ledger coordination domain, never the inner non-reentrant Ledger.lock byte lock L3. An existing dispatch-domain guard may serve as L2 ONLY after audited coverage proves every ledger/closure mutator AND inner-lock user is enrolled/drained through it, including direct register/reserve/finish calls, not just Gateway.dispatch. The current code does not automatically provide that complete coverage. Without it, use I/X; do not claim A/S. Future integration requires separate authorization and must leave F01 ownership/lease/fence/pin/exclusive primitives and existing API behavior unchanged.

The observer holds L1 then L2 during B..E but does NOT hold L3 across calls to existing verifier/ledger helpers. Participating operations acquire outer L2 before their ordinary inner L3, so acquiring L2 drains them and lets the unmodified verifier acquire/release L3 normally without recursive locking. A read-only pinned-buffer parser may inspect ledger bytes without L3 reentry. The future implementation must prove the exact guard identities/order and absence of bypassing inner-lock users; it cannot assume nested OS locks are reentrant. If unavailable, downgrade instead of inventing feasibility.

The verifier context must not own another session's lease or fabricate filesystem inputs. Calling the existing verification CORE is not replacing its checks; the public wrapper's error logging/translation stays unchanged for current callers. A future observation adapter may defer its own new error/diagnostic logging until after release; it may not monkey-patch verification, claim/release an owner lease, write capture inputs or normalize a failure into success. Generic I/O/programming failures remain errors. Capture-owned outputs (if persisted) are written only after the sealed cut, outside its input inventory.
