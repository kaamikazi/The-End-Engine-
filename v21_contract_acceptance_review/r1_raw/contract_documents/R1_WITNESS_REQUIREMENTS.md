# Exact required inventory and independent witness predicates

Acquisition inventory includes ALL names/types/content/absences in the declared run namespace, not just expected files. Account-graph authority and raw-source validity are distinct. Each file's recording origin is execution-only captured local writer provenance under the stated trust model; a matching checksum by itself establishes byte equality, not origin.

| Full actual ledger envelope and own rows | Integrity/strict types/global unique ordered reservations; all own IDs retained, no erased/orphan cover gaps | Self-checksum alone not authority; conflicting rows remain observed, not repaired |

Dispatch/settlement group may still support narrower identity without pretending reservation exists |

| Per-ID settlement witness | Mandatory for settled A identities; exact row equality/identity/state/handle/content/usage commitments | Missing => stable S/unknown cost; contradictory => S/conflict. Original metadata may remain observed |

| Closure/owner/prepared/source artifact (if source view requested) | Same-cut current existing completed-verifier proof required for eligible source view | No new owner/fence. Prior suspect RESULT/prepared remains immutable; R1 cannot grant eligibility |

Mandatory settled A graph is reservation + dispatch + response commitment/registered anchor + settlement + exact ledger row + run identity for each covered ID, and complete classified namespace membership. A raw journal may be missing/corrupt while the independent anchored graph still closes; then only scoped count/metadata observations qualify and normal provenance is BLOCKED. A genuinely in-flight reservation without settlement does not satisfy settled A graph; preserve its charged recorded identity under S/I with unknown cost. Positive zero needs a guarded complete empty set and absence of contradictory independent events. Global shared-ledger rows remain part of integrity checking; the reported scope includes only this run's bound IDs.

Every output-handle reference additionally requires original task/call/run/attempt, wire/provenance hash equality, uniqueness, settled-before-reference ordering and bound parent candidate identity. No unknown/rebound handle becomes selected. Raw metadata10/5/15 is recorded evidence, never an authenticated provider bill. Fully verified cost additionally requires raw usage/settlement/closure coverage; missing/unknown/inconsistent source cannot be summed into a total.

For known raw duplicate classification the captured file identity/content/chain must establish the SAME anchored ID/representation, with no additional independent claim. If undecidable, classify unexpected and downgrade rather than assuming it is harmless. A file alias/hard link is one source, not two independent witnesses. No existing current helper's VERIFIED status replaces this inventory/predicate list.

## Version-bound input schemas and digest meanings

The immutable baseline is checkpoint eadf1390c0631cfe30985744b38bb4df055acb87, specifically src/shared/{publication,journals,provenance}.py and the unchanged ledger contract. The future parser validates these actual source formats, not an unversioned guessed record:

- Run identity schema_version abc-r2-run-v1; requested/effective contract digests, run/task/condition, ledger/output binding and mode match the preexisting Publication identity. identity_sha256 means SHA-256 of the existing canonical identity VALUE (UTF-8 sorted-key compact JSON with finite values), not an arbitrary raw-file digest.
- Ledger envelope has state/state_sha256; the state schema is lab-ledger-v1. Verify existing canonical state digest, limits, runs and globally unique ordered attempt IDs before projecting own rows. Never infer an absent own ID from filtering a corrupt global ledger.
- Reservation witness schema abc-r3-reservation-v1 has exactly schema_version, identity_sha256, run_id, attempt_id, reservation. Its captured reservation binds attempt_id/run_id/purpose/token_ceiling/seconds_ceiling/started_unix to the current row; its execution-only origin is separately evidenced. Presence is mandatory for new A even when the legacy verifier treats absence as admissible.
- Dispatch anchor schema abc-r2-dispatch-anchor-v1 has the current exact fields schema_version,identity_sha256,run_id,attempt_id,stage,call_id,spec,reference_wire_sha256,provenance_sha256,wire_sha256,journal_path,header_sha256,model_request,structured,seed. Recompile/validate the actual sealed public intent/setting/reference contract as the baseline requires; do not invent a weaker purpose-only match.
- Settlement schema abc-r3-settlement-v1 has exactly schema_version,identity_sha256,run_id,attempt_id,settlement,dispatch_anchor_sha256,response_anchor_sha256. Check full canonical settlement-to-row equality and the RAW-byte digests of captured dispatch/response files. A changed current row does not retroactively alter the original witness.
- Registered response anchors have kind,run_id,attempt_id,stage,last_sha256 and raw_sha256 only for RAW_RESPONSE_RECEIVED; TRANSPORT_STOP has no fabricated raw-response digest. Current journal records use abc-r2-journal-v1 with exact index/previous/record hashes, header/tail state schema and raw-byte/base64/decoded response equality per baseline.
- Explicitly witnessed NO_RESPONSE (nullable response commitment in a matching failed/interrupted settlement) is distinct from disappearance of an expected non-null registered response. For anchored identity cardinality a supported failure disposition may close that dimension without a fabricated response; missing an expected commitment cannot. Unknown usage remains unknown and no complete totals follow. A reservation still in flight without required settlement cannot qualify as settled A.

evidence_ref.sha256 always hashes exact CAPTURED RAW BYTES, without newline/Unicode/reencoding normalization. Logical identity/state/record digests use their existing baseline canonicalization. Snapshot inventory_digest/content_digest hash the canonical manifest of sorted canonical names, entry/file identities, raw hashes and explicit missing descriptors, not just a list of expected digests. Publication.sha256 is the RAW referenced source-file digest; it is not the legacy artifact_payload_sha256 (which covers canonical payload excluding its own field). The unchanged source verifier checks both existing bindings before an eligible view is emitted. Do not substitute one digest domain for another.

Capture manifests are separately versioned evidence artifacts (protocol_id R1-GUARDED-CUT-2.1), not RunOutcome members or certificates. Their semantic fields and release ordering are fixed by ACQUISITION. A standalone extractor can preserve/report its lower facts in such a manifest/error context even when no persisted source terminal exists. It must not label that manifest a normal result or force it through the outcome union. No manifests or historical witnesses are produced by this documentation task.
