# Opt-in version detection and legacy-reader contract

No change to existing execute(), Session or Publication return/exception behavior is authorized. The future separately named opt-in adapter remains a proposal; it must complete the R4 caller inventory and supported-boundary review before implementation. Version routing happens BEFORE any field-shape projection.

1. Exact schema_version=end-outcome/2.1-proposal.1 AND contract_version=end-certification/2.1-proposal.1 route only to the v2.1 structural+semantic validator. Missing/mismatched version, unknown variant, mixed fields or contradictory flags reject. Do not guess a version from a result-looking fragment.
2. A version-aware legacy-normal reader MUST reject any schema_version/variant envelope. An archived original normal result with no new discriminator is accepted only after its ORIGINAL full payload/identity/prepared/owner/closure/provenance verifier succeeds; absence of a tag alone never proves a valid legacy normal.
3. Current abc-r3-blocked-recovery-v1 + is_completed_result=false is explicitly a current diagnostic, not a legacy normal. Its old fields are not converted into trusted RunResult by shape. Keep original bytes and old validators, not retroactive tags.
4. V2.1 contains no outer or embedded result/C0/FINAL/legacy payload object. A shape-only old reader requiring those fields fails closed on a v2.1 diagnostic. Forging such fields is additionalProperties violation. A consumer that ignores every discriminator and invents trust from arbitrary JSON is outside the compatibility guarantee; documentation cannot force arbitrary unknown code to reject. It must not be handed new envelopes through a silently changed old entry point.
5. Typed integrity rejection is an exception channel. Converting only a recognized grounded cause into a separate member3 diagnostic is an explicit future adapter operation, not a generic serialization of exceptions or a broad catch. Snapshot-unavailable diagnostics report UNKNOWN authority, not fabricated BLOCKED provenance. Unrelated storage/programming failures propagate.

Required reader tests: archived/current legacy normal positive; current diagnostic reject-as-normal; all exact three v2.1 variants accept only at opted-in reader; missing/unknown/mixed versions reject; legacy fields forged into diagnostic reject; true/false/null/absent completion substitutions reject; no candidate observation/no eligible candidate/known-empty states remain distinct. Validate exact underlying source proof and same-cut authority, not merely field names. External consumers remain UNKNOWN and no broad backward-compatibility promise is made.
