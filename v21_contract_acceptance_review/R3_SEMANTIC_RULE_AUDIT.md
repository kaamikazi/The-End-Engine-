# Independent audit of fourteen normative semantic rules

**ACCEPT as prospective requirements.** All fourteen rules are normative additions to the structural Draft-07 grammar, not executable JSON Schema keywords. This audit evaluates precision, testability, consistency and safe treatment of unavailable/conflicting evidence. `r3_raw/independent_r3_review.py` and its synthetic fixtures were authored independently from the specification; no author checker was used. They exercise selected predicates with declared external oracles and do not constitute real F01/capture/origin verification.

Rule references below are to R3_SCHEMA_SPECIFICATION.json:2260–2316. R1_ACQUISITION and WITNESS documents supply the external predicate definitions. No blocking contradiction was demonstrated.

The raw semantic results deliberately include **structurally accepted but semantically rejected** instances. That demonstrates why standard-library success must never be relabeled complete contract acceptance. All 35 independent semantic expectations match; this number denotes bounded synthetic review controls, not implementation coverage of every rule or successful real capture verification. All eight strict-parser expectations match. The separately retained Python3.12 rpds import failure is an environment/setup event, not one of these assertions.

Unavailability is handled without inventing corruption: snapshot-unavailable/unsupported diagnostics have UNKNOWN provenance and I/U/X. Known stable accounting contradictions return S/lower facts; detected in-cut violations U with no retry in that epoch. An unavailable common cut cannot produce a current eligible v2.1 terminal even if an earlier legacy result remains immutable. A real BLOCKED journal still vetoes eligibility independently of R1 observations. Generic I/O/programming faults remain actual errors. These distinctions are sufficiently explicit to implement without a new normative design choice.

Remaining scientific limitations are deliberate: local recording origin relies on qualified cooperative-writer/capture trust, not signatures or hostile-host resistance; no claim proves model inference, authentic provider billing, semantic answer correctness or empirical performance. No new mandatory redesign is warranted from those stated limits.
