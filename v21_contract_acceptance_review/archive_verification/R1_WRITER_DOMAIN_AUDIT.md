## Ordering judgment

The proposed order is L1(run) → L2(actual shared ledger) → ordinary L3 for participating operations. Current ordinary Session already takes L1 before Gateway boundary lock, then Ledger.lock. The observer must hold L1/L2 and leave L3 unheld across source verification. This avoids the obvious same-thread non-reentrant L3 deadlock. No code in `_verify_completed` acquires L1/L2 or an ownership lease; its reads can operate against pinned unchanged resources while acquiring L3 normally. The future adapter must not call generation/closure/writer helpers from the observer.

Multiple runs may each hold their own L1 and wait on shared L2 without a cycle if no holder of L2 subsequently takes a different run's L1. Inventory all bindings and other lock users before asserting that condition. This exact audited order is a testable requirement; current source is not a proof that every unknown caller follows it. A bounded native observer lock method is also needed because existing blocking `dispatch_lock` is not a five-second observer interface. An additive timed acquisition using the same native lock identity is not inherently an owner/fence change. If safe enrollment/timeout/native sharing cannot be proven, I/X remains mandatory.

## Trust classifications

- CURRENT_IMPLEMENTATION_FACT: listed functions, actual locks and writes are directly visible in source. Current graph checks use shallow globs, and reservation presence is optional (`provenance.py:76–99`); they are insufficient authority tokens for the new extractor.
- PROPOSED_IMPLEMENTATION_REQUIREMENT: audited domain, complete recursive inventory, original-witness origin, bounded waits, strict sealed parser and same-cut verification remain unimplemented future engineering.
- REVIEWED_TRUST_ASSUMPTION: qualified local cooperating writers and capture producer origin; digest equality alone cannot attest origin. Complete malicious-host resistance is excluded by the contract.
- UNKNOWN_IMPLEMENTABILITY: actual future deployment/process coverage and platform/native handle feasibility until implemented and tested. No unavoidable contradiction was demonstrated; specified I/X downgrade contains this uncertainty.

This audit grants no runtime A/S and no owner changes. It adds no new mandatory redesign beyond the already declared domain and preserved R4/R5 gates.
