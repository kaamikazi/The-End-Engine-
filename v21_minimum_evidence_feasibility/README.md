Owner approved the bounded offline study in this chat on 2026-10-23 (Asia/Dhaka). This directory is the only new write/scratch boundary. The approved implementation is read only at `E:/The End Engine/v21_A0_feasibility/checkout`, commit `783aa1d23ba2ca8c4fd28cdaf993ea2f66b5294e`.

The gate excludes only participants which actually use it. Direct Ledger APIs, other source writers, administrators and unknown actors are not presumed enrolled. Source census is not proof of exclusion; no A/S is awarded by this test harness.

The six-condition inputs are existing deterministic mock artifacts under `E:/The End Engine/ir101_fix/wiring/mock_wiring`, task EXP-001. They are reused without running any condition, Engine, Harness, provider, scorer or benchmark. Raw copies remain byte-identical. Complete mock fixture arithmetic is never complete provider accounting.

## Fixed execution and scoring

1. Capture original bytes/membership/Git identities and verify prior integrity receipts.
2. Inspect original six-condition rows and evidence; archive their raw bytes. Run six unchanged nonowning core checks on derived mock copies, with no owner lease.
3. Nine isolated data faults: missing dispatch, missing settlement, duplicate attempt, changed response content, unknown tokens, incomplete receipt, interrupted outstanding attempt, corrupt journal, missing candidate binding. Save the fault before checking it. Rejection must match the predeclared exact source status/error; unexpected exceptions are FAIL, never PASS.
4. One real-process concurrent write attempt against pinned existing evidence: require native denial, preserved bytes, joined child and post-release access.
5. One two-participant cooperating admission/drain positive, limited to those actors.
6. Last, execute the exact corrected A0-18 on a new scratch copy. One execution supplies two separately named assertions: real unenrolled Ledger.register bypass and new pending foreign registration. Retain the replacement denial separately. Stop this profile when the known domain violation is observed; no subsequent writer/capture experiment or profile retry.

There are twelve required fault categories and eleven distinct negative executions: categories 1 and 2 intentionally share one actual register operation and are not counted as two executions. Historical A0 19 PASS/1 ERROR, author correction 1 PASS and prior independent 1 PASS stay separate.

Each whole worker command has a 60-second watchdog, original native worker waits are at most 10 seconds with parent cleanup; fixed A0 guards at most 5 seconds, no more than two acquisitions. Unexpected timeout, missed marker, incorrect diagnostic, unjoined child or handle leak fails. The negative record includes observed_event, expected_event, elapsed_time, bound_satisfied, control_verdict and feasibility_implication. No retry-until-green.

Accounting vocabulary: RESERVED is recorded admission; DISPATCH_OBSERVED is only the original mock transport/anchor evidence; RESPONSE_RECEIVED is an actual retained mock receipt; SETTLED is the ledger state with corroboration named separately; UNKNOWN_OUTCOME retains nulls. COMPLETE_ACCOUNTING requires a demonstrated A cut, current unchanged independent eligibility, closure, all required dispatch/raw/usage/settlement links, exact arithmetic and no uncertainty. PARTIAL_ACCOUNTING retains named known facts with null unsupported totals. UNKNOWN_ACCOUNTING has no grounded relevant accounting facts. INVALID_COMPARISON covers missing, conflicting or differently scoped endpoints. Reservation count, locally generated checksum and canned receipt do not prove actual inference or billing.

Final verdict precedence, fixed before execution: an actual tested exclusion bypass gives WRITER_EXCLUSION_BLOCKER; otherwise a demonstrated required call/usage gap gives ACCOUNTING_COMPLETENESS_BLOCKER; unresolved material evidence gives ADDITIONAL_FEASIBILITY_REQUIRED; only all supported precisely scoped mechanisms permit LIMITED_EXPERIMENT_EVIDENCE_PATH_SUPPORTED. Independent Gate 2 gaps remain reported even if Gate 1 controls the single verdict. No verdict authorizes inference or constitutes runtime acceptance.

No production implementation, writer enrollment, contract/F01/F02/F03/F04/algorithm/prompt/task/evaluator changes, old-test migration, live calls, benchmark, installation or Git commit/push/merge/release. Only this directory is changed. The final ten requested reports are written after finite execution and preservation; raw failures are retained.
